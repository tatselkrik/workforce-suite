# BIR declaration file builder

Payroll Officers and Administrators prepare explicit declaration values in a schedule-specific CSV/native
Excel template. Its columns correspond to published detail columns7 onward;
HRIS supplies only employer/form/period, deterministic row-order sequences and
exact monetary controls. It never guesses tax, income classes, eligibility,
dates, nationalities, region codes, prior-employer amounts or filing declarations.
Blank amounts are errors, not zero. Existing payroll/source review remains a
separate worksheet and does not automatically populate return boxes.

References rechecked27October2026:
- [RMC25-2024 AnnexA](https://bir-cdn.bir.gov.ph/BIR/pdf/RMC%20No.%2025-2024%20Annex%20A.pdf),
  pages6–9: standalone49/36 and59/45 detail/control layouts.
- [RMC15-2025 AnnexB](https://bir-cdn.bir.gov.ph/BIR/pdf/RMC%20No.%2015-2025%20Annex%20B.pdf):
  annual TIN + branch + MMDDYYYY +1604C.DAT filename.

Keep sources local/unchanged, at most2MiB/500details and one schedule. Use the
existing bounded Excel reader; identifiers/amounts remain template text, with
no formula evaluation, external links, macros or hidden/merged data. Preserve
literal names and identifiers; reject unsupported encoding/delimiters rather
than transliterating or shortening. Generated drafts use ASCII/no BOM/CRLF and
explicit two-decimal PHP. Control overflow fails instead of splitting/dropping
employees. Published supported subtotal checks must pass; ambiguous tax/combined
compensation relationships are never invented.

The preview must bind company/account, schedule/year, exact source bytes, current
protected employer registration revision and generated bytes. Saving repeats
fresh reads/rendering, rejects a stale preview, requires explicit HR declaration
review and rechecks current access immediately before new-file-only IO. Generated
DAT contains tax identifiers and declared pay; minimal diagnostic findings retain
their separate promise to omit that data. No upload, database write, registration
edit, receipt/payment, official runtime execution or filing is part of building.

Before delivery verify both schedules, all monetary/control boundaries, physical
rows, ASCII/no-silent-change rules, CSV/Excel parity, exact cents/overflow, blank
values, stale source/registration/actor/year/schedule, current-role/revocation
denial, no-overwrite/source preservation and native layouts. Official7.4 behavior
and current encoding/region/eligibility acceptance remain separate deferred gates.
